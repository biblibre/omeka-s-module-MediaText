API REST

Media Text ajoute une nouvelle ressource d’API nommée mediatext_representations. Elle peut être utilisée via l”API REST d’Omeka S et l’API PHP ($api->search('mediatext_representations', ...)).

Les règles habituelles d’Omeka S s’appliquent : une authentification par identité de clé (key identity) et identifiant de clé (key credential) est nécessaire pour créer, modifier et supprimer des représentations, ainsi que pour lire les représentations privées (voir Visibilité).

JSON-LD d’une représentation

GET /api/mediatext_representations/:id

{
    "@context": "...",
    "@id": "https://example.org/api/mediatext_representations/1",
    "@type": "o-module-mediatext:Representation",
    "o:id": 1,
    "o:media": {
        "@id": "https://example.org/api/media/42",
        "o:id": 42
    },
    "o:type": "transcription",
    "o:format": "plain_text",
    "o:content": "The full text",
    "o:created": {
        "@value": "2026-07-28T10:00:00+00:00",
        "@type": "http://www.w3.org/2001/XMLSchema#dateTime"
    },
    "o:modified": {
        "@value": "2026-07-28T10:00:00+00:00",
        "@type": "http://www.w3.org/2001/XMLSchema#dateTime"
    }
}

o:content est retourné décompressé, dans son format d’origine (non converti en texte brut).

Valeurs de o:type : transcription, transliteration, translation, other.

Valeurs de o:format : plain_text, alto (et tout format ajouté par d’autres modules, voir Étendre Media Text).

JSON-LD d’un média

Le JSON-LD d’un média qui possède des représentations textuelles contient une clé supplémentaire, o-module-mediatext:representations, avec des références vers ces représentations :

{
    "@id": "https://example.org/api/media/42",
    "o:id": 42,
    "...": "...",
    "o-module-mediatext:representations": [
        {
            "@id": "https://example.org/api/mediatext_representations/1",
            "o:id": 1
        }
    ]
}

Recherche

GET /api/mediatext_representations

Paramètres de requête disponibles (en plus des paramètres standards comme page, per_page, sort_by, sort_order) :

Paramètre

Description

media_id

ID du média

title

Titre exact

type

Type (transcription, transliteration, …)

format

Format (plain_text, alto, …)

sort_by accepte : id, title, type, format, position, created, modified.

Exemple : toutes les représentations du média 42, dans l’ordre

GET /api/mediatext_representations?media_id=42&sort_by=position&sort_order=asc

Recherche de contenus et de médias

Le paramètre mediatext_has_textual_representations (1 ou 0) peut être passé à /api/items et /api/media pour filtrer les ressources selon la présence de représentations textuelles. Il n’est pris en compte que pour les requêtes d’administration (voir Recherche).

Créer

POST /api/mediatext_representations

Les représentations sont créées via un ingesteur (voir Étendre Media Text), indiqué par o:ingester. Avec l’ingesteur textarea, le contenu est fourni dans la clé content :

{
    "o:media": {"o:id": 42},
    "o:title": "Transcription",
    "o:type": "transcription",
    "o:format": "plain_text",
    "o:is_public": true,
    "o:ingester": "textarea",
    "content": "The full text"
}

Avec l’ingesteur upload, envoyez une requête multipart/form-data avec les données JSON dans le champ data, le fichier dans upload_file[<index>], et le même <index> dans la clé file_index des données JSON. Le nom du fichier est enregistré comme source, sauf si o:source est fourni.

Le contenu est validé en fonction de son format ; les erreurs de validation sont retournées de la manière habituelle par l’API.

Note

Une représentation créée de cette manière reçoit la position 0. Utilisez la mise à jour du média décrite ci-dessous pour contrôler l’ordre des représentations.

Modifier

PATCH /api/mediatext_representations/:id (ou PUT)

Clés acceptées : o:title, o:type, o:format, o:is_public, o:content. Le contenu est validé en fonction du format.

Supprimer

DELETE /api/mediatext_representations/:id

Gérer les représentations via le média

Les représentations peuvent aussi être gérées lors de la mise à jour d’un média (PUT/PATCH /api/media/:id), avec la clé o:mediatext_representation. C’est ce qu’utilise l’interface d’administration. Lorsque cette clé est présente :

  • ses éléments sont traités dans l’ordre et leur position est définie en conséquence,

  • un élément avec un o:id conserve une représentation existante ; son o:is_public peut être modifié,

  • un élément sans o:id crée une nouvelle représentation (mêmes clés que pour Créer, sans o:media),

  • les représentations existantes du média qui ne sont pas listées sont supprimées.

{
    "o:mediatext_representation": [
        {"o:id": 3},
        {"o:id": 1, "o:is_public": false},
        {
            "o:title": "Translation",
            "o:type": "translation",
            "o:format": "plain_text",
            "o:ingester": "textarea",
            "content": "..."
        }
    ]
}

Des clés supplémentaires sont acceptées lors de la mise à jour de médias et de contenus (y compris les mises à jour par lot) :

mediatext_remove_representations

all pour supprimer toutes les représentations, extracted pour supprimer uniquement les représentations extraites automatiquement. Pour les contenus, s’applique à tous leurs médias.

mediatext_extractors

Un tableau de noms d’extracteurs (pdftotext, odt2txt, docx2txt, catdoc, tesseract) à exécuter sur le média (pour les contenus, sur tous leurs médias). Voir Extraction automatique du texte.

À la création d’un média, tous les extracteurs disponibles sont exécutés automatiquement.
