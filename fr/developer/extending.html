Étendre Media Text

D’autres modules peuvent étendre Media Text en fournissant de nouveaux formats, ingesteurs et extracteurs. Chacun d’eux est un plugin, enregistré dans la configuration du module (config/module.config.php) sous une clé dédiée, à l’aide des sections habituelles invokables et factories.

Plugin

Clé de configuration

Interface

Adaptateur de format

mediatext_format_adapters

MediaText\Format\Adapter\FormatAdapterInterface

Ingesteur

mediatext_representation_ingesters

MediaText\Representation\Ingester\RepresentationIngesterInterface

Extracteur

mediatext_representation_extractors

MediaText\Representation\Extractor\RepresentationExtractorInterface

La clé utilisée pour enregistrer un plugin est son nom. Elle doit être identique à la valeur retournée par sa méthode getName().

Adaptateurs de format

Un adaptateur de format valide le contenu d’une représentation et le convertit en texte brut (pour l’affichage et l’indexation).

'mediatext_format_adapters' => [
    'invokables' => [
        'tei' => \MyModule\MediaText\Format\TeiAdapter::class,
    ],
],

namespace MyModule\MediaText\Format;

use MediaText\Format\Adapter\AbstractFormatAdapter;
use Omeka\Stdlib\ErrorStore;

class TeiAdapter extends AbstractFormatAdapter
{
    public function getName(): string
    {
        return 'tei';
    }

    public function getLabel(): string
    {
        return 'TEI'; // @translate
    }

    public function validate(string $representation, ErrorStore $errorStore): void
    {
        // Add errors to $errorStore to prevent the representation from
        // being saved
        if (trim($representation) === '') {
            $errorStore->addError('', 'Representation is empty'); // @translate
        }
    }

    public function getPlainText(string $representation): string
    {
        // Convert $representation to plain text
    }
}

AbstractFormatAdapter implémente getSortableString() (les formats sont triés par libellé dans les listes déroulantes).

Ingesteurs

Un ingesteur fournit un moyen de créer une représentation textuelle depuis le formulaire de modification du média (et depuis l’API, avec o:ingester). Media Text fournit deux ingesteurs : textarea et upload. Chaque ingesteur apparaît sous forme de bouton dans la section Importer une représentation textuelle de la barre latérale.

namespace MyModule\MediaText\Ingester;

use Laminas\View\Renderer\PhpRenderer;
use MediaText\Entity\Representation;
use MediaText\Representation\Ingester\AbstractRepresentationIngester;
use Omeka\Api\Request;
use Omeka\Stdlib\ErrorStore;

class Url extends AbstractRepresentationIngester
{
    public function getName(): string
    {
        return 'url';
    }

    public function getLabel(): string
    {
        return 'URL'; // @translate
    }

    public function form(PhpRenderer $view): string
    {
        // Title, type and format fields
        $form = parent::form($view);

        $url = new \Laminas\Form\Element\Url('o:mediatext_representation[__index__][url]');
        $url->setLabel('URL'); // @translate
        $form .= $view->formRow($url);

        return $form;
    }

    public function ingest(Representation $representation, Request $request, ErrorStore $errorStore): void
    {
        $data = $request->getContent();
        if (empty($data['url'])) {
            $errorStore->addError('url', 'No URL was specified'); // @translate
            return;
        }

        $representation->setContent(file_get_contents($data['url']));
        $representation->setSource($data['url']);
    }
}

Remarques :

  • form() retourne le HTML des champs du formulaire. Les noms des champs doivent être de la forme o:mediatext_representation[__index__][...] ; __index__ est remplacé en JavaScript par l’index de la représentation. AbstractRepresentationIngester::form() retourne les champs Titre, Type et Format.

  • ingest() doit appeler $representation->setContent(), et peut appeler $representation->setSource(). Les données de la requête contiennent uniquement les champs du formulaire de cette représentation. Les fichiers chargés sont accessibles avec $request->getFileData().

  • La validation et la compression du contenu sont effectuées par Media Text après ingest().

Extracteurs

Un extracteur crée automatiquement des représentations textuelles à partir d’un média.

'mediatext_representation_extractors' => [
    'factories' => [
        'myocr' => \MyModule\Service\MediaText\MyOcrFactory::class,
    ],
],

L’interface impose les méthodes suivantes :

getName(): string et getLabel(): string

Nom et libellé lisible. Le libellé est utilisé dans le titre par défaut des représentations extraites (« Extrait par <libellé> »).

isAvailable(): bool

Indique si l’extracteur peut être utilisé sur ce serveur (par exemple, si le programme requis est installé). Les extracteurs non disponibles sont masqués dans le formulaire de modification par lot et désactivés dans le formulaire de modification du média.

canExtractFrom(MediaRepresentation $media): bool

Indique si l’extracteur prend en charge ce média (généralement en fonction de son type de média).

getRepresentations(MediaRepresentation $media): array

Retourne un tableau de nouveaux objets MediaText\Entity\Representation. Chacun doit avoir au minimum un type, un format et un contenu (défini avec setContent()).

Media Text se charge ensuite du reste : rattacher les représentations au média, définir leur titre (s’il est vide), leur position, leurs horodatages et leur indicateur « extraite », et compresser le contenu.

Pour les extracteurs qui travaillent sur le fichier original du média, étendez MediaText\Representation\Extractor\AbstractFileRepresentationExtractor et implémentez getRepresentationsFromFile(string $filepath): array. La classe abstraite récupère un chemin local vers le fichier (en le téléchargeant si le stockage des fichiers n’est pas local) et définit la source des représentations à partir de la source du média. Le stockage des fichiers et le téléchargeur doivent être injectés dans la fabrique (factory) :

namespace MyModule\Service\MediaText;

use Laminas\ServiceManager\Factory\FactoryInterface;
use MyModule\MediaText\Extractor\MyOcr;
use Psr\Container\ContainerInterface;

class MyOcrFactory implements FactoryInterface
{
    public function __invoke(ContainerInterface $services, $requestedName, ?array $options = null)
    {
        $service = new MyOcr($services->get('Omeka\Cli'));
        $service->setDownloader($services->get('Omeka\File\Downloader'));
        $service->setFileStore($services->get('Omeka\File\Store'));

        return $service;
    }
}

Voir src/Representation/Extractor/Tesseract.php pour un exemple complet.

API PHP

MediaText\Api\Representation\RepresentationRepresentation fournit les méthodes suivantes, utiles dans les thèmes et les modules :

Méthode

Description

media()

Le média (MediaRepresentation)

title(), type(), format(), source(), position()

Propriétés de la représentation

typeLabel(), formatLabel()

Libellés lisibles du type et du format

isPublic(), isExtracted()

Visibilité et indicateur « extraite automatiquement »

content()

Le contenu, décompressé, dans son format d’origine

contentAsPlainText()

Le contenu converti en texte brut par l’adaptateur de format

created(), modified()

Horodatages (DateTime)

Exemple, dans la page d’un média d’un thème :

<?php
$representations = $this->api()->search('mediatext_representations', [
    'media_id' => $media->id(),
    'sort_by' => 'position',
    'sort_order' => 'asc',
])->getContent();
?>
<?php foreach ($representations as $representation): ?>
    <h3><?= $this->escapeHtml($representation->title()) ?></h3>
    <pre><?= $this->escapeHtml($representation->contentAsPlainText()) ?></pre>
<?php endforeach; ?>
